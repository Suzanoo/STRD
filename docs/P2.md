## Setup and use

Python 3.10+ with Tk, local macOS filesystem; Linux is Work's verification platform.
Install the delivered wheel in a fresh environment from repository root:

```sh
python3 -m tkinter
python3 -m venv .venv-p2
.venv-p2/bin/python -m pip install --no-index --no-deps /PATH/strd_engine-0.4.0-py3-none-any.whl
.venv-p2/bin/python -m strd.desktop
```

`bash scripts/start_p2_macos.command` or `.venv-p2/bin/strd-desktop` starts the same
application. No network/runtime dependencies added. Python/Tk is required; this is not
a signed standalone .app. P1 launcher remains available for its existing environment.

- New creates an unsaved project with a blank member. Edit project title in the toolbar.
- Add Member, Duplicate and Remove manage independent members. Picker shows an ordinal
  as well as editable member ID; stable internal member identities are distinct from labels.
- The P1 member/case/segment editor and calculation trace are retained. Calculate applies
  only to the selected member; no project-level PASS is inferred from other members.
- Save writes all drafts, even unfinished numeric text. Saving is not engineering validation.
  Asterisk and Unsaved changes show edits; calculation alone does not dirty the input file.
- Save As uses a new destination. An unrelated existing destination is rejected even if
  the system file dialog offers overwrite confirmation. Choose a new filename instead.
- Open validates a candidate fully before replacing live work. New/Open/Close offer
  Save / Discard / Cancel for unsaved work; failed/canceled saves keep the current project.
- Every reopened member requires recalculation. Runtime results are not serialized.
- `examples/p2_two_members.strd` is a labeled demonstration: the first member passes
  implemented checks, the second fails flexure. Replace demands/assumptions for real work.

Limits: 100 members, 100 segments and 100 cases per member; 16 MiB project file;
4096 characters per text field. Exceeding limits is rejected, never truncated.
Window minimum 960x760; vertical scrollbars expose lower input controls.

## File identity, compatibility and snapshots

UTF-8 JSON `.strd` envelope contains canonical-payload SHA256 (corruption detection,
not a signature). Payload STRD-PROJECT-1 has project UUID, title, writer package version,
exact engineering basis/manual hash/calculator/assessment IDs, full verified catalog
snapshot, explicit RECALCULATE_ON_OPEN policy and stable member UUID/draft entries.
No pickle, executable content, object restoration or stored PASS/capacity is loaded.
Duplicate keys, malformed structure, nonfinite JSON numbers, unknown fields and altered
checksums fail closed. Draft text such as blank or "not ready" can roundtrip faithfully;
engineering success still requires the unchanged assessment service.

P1 had no project format to migrate. Only STRD-PROJECT-1 is readable in P2; unsupported
older/future schemas are rejected without modifying the source. Exact engineering and
catalog snapshots must match the installed verified basis. Package writer version is
provenance, not by itself an engineering compatibility rule. Different catalog/basis
requires a separately verified migration with preserved source, not silent replacement.
No automatic migration, arbitrary catalog import or legacy CSV promotion is implemented.

## Save integrity, recovery and conflicts

Local macOS/POSIX files only. A persistent `<project>.lock` sidecar uses OS advisory
locking during save. It is deliberately not deleted: deleting it can split cooperating
writers onto different locks. OS releases held locks on process death; do not remove a
lock sidecar while STRD instances may be active. No force-unlock command is needed.

Inside the lock, compare current file bytes with the SHA256 observed at Open/Save.
A stale writer or a deleted target is rejected. Save As to a new path is create-only,
including an atomic exclusive creation at commit; it does not overwrite another file.
Stage in the same directory, flush/fsync, verify readback, then replace. On replacement
save, stage and sync the previous valid revision as `<project>.bak` before replacing
primary. Sync the directory after changes. File/backup permissions are owner-only.
Symlink/hardlinked files and unsafe sidecars are rejected; directory aliases resolve to
a single target identity. Failed pre-commit saves preserve primary and live drafts.
A post-commit directory-sync failure is reported as uncertain, not Saved: reopen to
verify or Save As a new name. Do not repeatedly force an old session onto that file.

Recover backup lets you choose the original project OR its .bak. It validates and opens
that previous successful revision as an UNSAVED project with no current results. Save As
a NEW name; the corrupt original remains available for investigation. A backup appears
only after replacing a previously saved file; it is one previous revision, not history.

Recovery does not mean autosave: unsaved edits lost in a process crash are not recovered.
Save regularly. An interrupted save can leave `.pending-*` temporary files; do not treat
them as committed projects. Primary and .bak are the supported recovery path. First-save
crash before commit has no prior revision. No power-loss/hardware durability guarantee is
claimed beyond OS fsync/atomic operations; actual native macOS filesystem behavior remains
a separate acceptance gate. Keep ordinary external backups for hardware loss.

Locks protect cooperating STRD instances on one local filesystem. Network shares, cloud
sync folders, shared editing and external editors racing a save are outside scope.
A final byte recheck detects many external edits but cannot make non-cooperating writers
transactional. Never claim this is a distributed locking system.

Implementation references: Python os.replace/fsync and fcntl.flock documentation:
https://docs.python.org/3/library/os.html and https://docs.python.org/3/library/fcntl.html .

## Architecture and verification

`workspace/format.py`: schema, bounds, provenance, snapshot checks and canonical bytes.
`workspace/storage.py`: local disk protocol; no Tk or engineering formulas.
`workspace/__init__.py`: project/session ownership, dirty state and transactional Open.
`desktop/project_ui.py`: native dialogs and collection workflow over the P1 editor.
P1 result rendering is extracted for selected-member reuse. Generated case/segment IDs
skip existing labels, preventing collisions after restoring/duplicating editable drafts.
The accepted engineering implementation, catalog and compatibility fixtures are unchanged.

See TESTING.md and delivery evidence. Automated tests cover fault injection and actual
subprocess concurrency/abrupt exit, plus real Tk widgets. Native chooser responses are
simulated for repeatability; native dialogs, macOS filesystem and PO usability are not
inferred from those tests. P3 reporting/export, release packaging and new checks excluded.

## PO native acceptance (after Coordinator review)

Work executes engineering/safety regressions independently. PO participation is limited to
macOS-specific operation and product acceptance:

1. Install/launch 0.4.0 on intended macOS/Python/Tk. Verify native Open/Save dialogs,
   Unicode/spaces in a local directory, keyboard focus, scrolling and display sizing.
2. Open sample, switch members, calculate, edit and save as a new file. Close/reopen;
   confirm all drafts survive and results require recalculation. Check Save/Discard/Cancel.
3. On disposable copies, launch two native instances. Save in one, attempt save in the
   other: conflict leaves its edits intact and Save As works. After two saved revisions,
   damage a disposable primary and Recover backup into a new name; original stays untouched.
4. Accept/revise P2 workflow and stated limits. Record actual macOS/Python/Tk versions.

No need to manually repeat Work's injected disk-failure, malformed-schema or subprocess
regressions. Native results are additional platform evidence, not engineering work delegation.
No automatic P3/Git authority follows acceptance.
