4. REUSE AND REFACTOR DISPOSITION
================================

REUSE AS CANDIDATES — AFTER VERIFICATION:
- Chapter-oriented intent in applications/ and tools/
- H-section data subset with independent provenance/precision checks
- Individual mathematical helpers where units and tests can be made explicit
- Roof workflow knowledge, prompts and diagrams as requirements evidence
- Beam solver architecture as a later analysis candidate, not first-release dependency

REPAIR / EXTRACT:
- Material/load records: add explicit units/basis without unnecessary frameworks
- Capacity functions: return structured results; move input/output outside arithmetic
- Classification: derive from geometry/material/source rules and route deterministically
- Catalog ingestion: strict schema, numeric and physical validation; no silent coercion to accepted NaN
- Shared helpers: consolidate only after checking behavior and callers

QUARANTINE FROM VERIFIED PRODUCT CLAIMS:
- Existing failing compression/LTB/interaction paths until repaired and tested
- All unverified cold-formed roof sizing and load combinations
- Experimental bolt/base-plate scripts
- Unfinished slender/FTB/built-up cases

DEFER:
- Full-building solver, CAD/BIM import, optimization, cloud collaboration/accounts
- All-section/all-chapter completeness
- Desktop/Web implementation decision until workflow and deployment needs are reviewed

Alternative assessment:
A. Wrap current scripts in a new UI: fastest visible result, but carries incorrect data/results and hidden scope; not recommended.
B. Verify/extract one useful member workflow, then expand: preferred; reuses evidence while bounding correctness.
C. Complete rewrite: not justified yet; loses useful prior work and does not automatically solve formula/data verification.
A new folder tree alone is not the recovery objective.

5. PROPOSED SHARED ENGINEERING RULES — NOT YET ACCEPTED
======================================================

R1. One explicit design basis per calculation.
Store book/standard title, edition, relevant clauses, approved deviations/errata, material source and catalog revision.
Do not silently modernize coefficients or mix book-era examples with another standard edition.
ASD and LRFD share appropriate nominal capacities, but factors and demand combinations are method-specific.
Do not derive ASD demand by dividing LRFD demand by a generic factor.

R2. Explicit units and sign/axis conventions.
Recommend internal N, mm, MPa; convert at input/output boundaries.
Store force vs mass distinctly; kg labels in legacy scripts require a documented interpretation.
Distinguish S_elastic from Z_plastic, section axes from global axes, member length from unbraced lengths.
Use full precision in calculations; round display only.

R3. Catalog as validated engineering data.
Stable section identity includes full dimensions/thickness, not HxB alone.
Keep source, units, edition, manufacturing category, precision and verified/unverified state.
Check number of columns, finite positive required values, geometry consistency and relations such as r²≈I/A within justified tolerance.
Derived properties need documented assumptions; missing source data must not silently become a default.
Only the subset needed for the accepted first scope must be verified initially; do not clean all catalogs speculatively.

R4. Traceable results rather than bare pass/fail.
Each check returns inputs, assumptions, clause/formula reference, intermediates, nominal/design strength, demand, ratio, applicability and governing check.
Statuses: PASS, FAIL, INVALID_INPUT, UNSUPPORTED, NOT_CHECKED.
An overall status must not imply serviceability/connections/global stability were checked when they were not.
Use "supported strength checks passed" where that is the actual scope.

R5. Separate calculation from interaction and storage.
Keep domain arithmetic independent from terminal prompts, UI, plotting and persistence.
Use the existing functions as reuse candidates; final file structure is an Engineer decision to justify against evidence.
Conceptual responsibilities: validated data; calculation rules; workflow orchestration; UI/report/storage adapters.
No requirement to build two UIs or a network API in advance.

R6. Save editable inputs independently from exported reports.
For the first product workflow, preserve project/member identity, units, assumptions, input forces, basis/catalog/calculator versions and result context.
Reopening must identify stale results if inputs/basis change.
Save failure must retain recoverable work; report output must match the actual recorded calculation.
This is a proposed STRD requirement, not an automatic transfer of Progress Studio's workbook model.

R7. Independent verification.
Book examples are reference evidence, not unquestionable test oracles.
Book p.142 example 10.6.1 states Pu=276 kN but later prints 279 in a weld-length expression; previously inspected page image confirms the inconsistency.
Record discrepancy and justified reference value instead of forcing software to duplicate a typo.
Use hand checks, intermediate assertions, boundary tests and negative cases as well as examples.
Do not mark two copies of the same implementation as independent verification.

6. FIRST USEFUL PRODUCT SCOPE — RECOMMENDATION
=============================================

Candidate: H-beam strength checker from supplied actions.
Why: connects existing h_beam/flexural code and H catalog to concrete book examples, and offers a clear end-user task.
Alternative: axial H-column checker is smaller, but currently lacks correct branch/factor/axis treatment and would still require similar data/validation foundations.
First-choice recommendation remains H-beam; PO may choose column based on actual work priority.

Proposed initial envelope:
- Rolled, doubly symmetric H section, compact flange/web for selected material.
- Major-axis bending and applicable web shear checks only.
- ASD and LRFD with separately specified demands.
- Explicit unbraced length and Cb assumptions/input; validate applicability and support/torsional restraint assumptions.
- No axial force, biaxial bending, torsion, slender/built-up sections, web openings or tension-field action.
- Concentrated load/local bearing/connection/global stability checks not included in this initial checker; state NOT_CHECKED and reject use beyond the accepted envelope where appropriate.
- No deflection result inferred from moment/shear maxima alone.
- Serviceability initially identified as separate/unverified, unless PO requests a separately scoped loading-model or imported-deflection feature.

Suggested input:
project/member reference; basis/method; section ID; material; Mu or Ma; Vu or Va; Lb; Cb and its basis; support/restraint assumptions.
Suggested output:
section classification; applicable checks; capacities and ratios; governing condition; calculation trace; all exclusions.

Product flow:
Create/Open project -> add member -> enter/validate -> calculate -> inspect trace -> change section and recalculate -> Save/Open -> export report.
Candidate comparison can follow later; first release need not contain an automatic optimizer.
