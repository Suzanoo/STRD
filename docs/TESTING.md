# Reproducible MS-1 tests

Run from the STRD repository root after applying the complete payload. Use Python 3.10 or newer (actual verification: Python 3.12.14 on Linux). Standard library only: no pip downloads, conda, numpy/pandas or legacy setup.py required for this proof. Python 3.10/3.11 and native Windows/macOS have not been executed in the delivery environment.

## Windows PowerShell

```powershell
py -3 -m venv .venv-ms1
.\.venv-ms1\Scripts\python.exe -m unittest discover -s tests_verified -v
.\.venv-ms1\Scripts\python.exe -m strd_verified
```

## macOS/Linux

```sh
python3 -m venv .venv-ms1
.venv-ms1/bin/python -m unittest discover -s tests_verified -v
.venv-ms1/bin/python -m strd_verified
```

The second command emits two JSON results (LRFD 310 and ASD 200 kN-m). It is an engineering smoke example, not a UI or project-storage workflow. API consumers may import check_bending from strd_verified when the repo root is on their Python path. This milestone distributes source, not an installable wheel; avoid using legacy setup.py as its entrypoint.

Unit/focused regression tests live in tests_verified/test_bending.py. The legacy yielding reuse test reads applications/flexural.py using explicit UTF-8 and extracts only the class, avoiding unrelated dependencies. The new calculation package itself does not read legacy files. Expected values come from reference literals and Decimal arithmetic, not snapshots generated by the production function.

Do not interpret syntax success or these focused tests as validation of legacy apps. Run all tests_verified after any scoped change. Record commands, versions, actual counts and failures; PO acceptance is a separate gate. Native desktop acceptance is not applicable to this headless proof.
