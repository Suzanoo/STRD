## Scope and architecture

- `strd.catalog`: checksummed versioned JSON resource; frozen SI section/material
  records; fresh inventory and provenance snapshots. Two real sections, one material
  envelope, no custom data imports or property overrides. Offline, no runtime packages.
- `strd.assessment`: request/coverage validation, independent per-check execution,
  case/segment identity, governing ratios with ties and explicit partial coverage.
- `engineering/dpt`: retained book calculations. Web geometry validation now requires
  only web-check properties; the old fixed-fixture API still performs its full reference
  integrity check before this kernel. All accepted public responses remain regression protected.
- `verification/a2_reference_calculations.py`: independent 50-digit Decimal audit from
  source literals, with geometric checks; never imported by production.
- No general section-property generator: all required values already exist in SYS.
  Audit formulas do not expose new engineering capabilities. No legacy catalog dependency.

Dependencies: assessment -> catalog + engineering; catalog -> domain + stdlib;
engineering -> domain + same-basis modules. No UI, database, network or legacy imports.
Package version 0.2.0; assessment version A2-1; old MS1-1/MS2-1 equation identities remain.

## Supported data and checks

Catalog revision `SYS-TIS-H-ED6-A2-1`:

| section_id | Actual d x bf x tw x tf (mm) | Nominal weight label |
|---|---|---|
| SYS-H-450x200x9x14-ED6 | 450 x 200 x 9 x 14 | 450x200x76.0 kg/m |
| SYS-H-500x200x10x16-ED6 | 500 x 200 x 10 x 16 | 500x200x89.6 kg/m |

Material `SYS-SS400-TLE16-DPT-E200000-v1`: Fy=245 MPa for web AND flange
thickness <=16 mm; E=200000 MPa retained from DPT. Other thickness ranges/grades
are unsupported. Supply certification and actual restraint are caller responsibilities.

Both records have compact flange/web under the accepted basis. Flexure supports
all three Lb regions and supported Cb assertions; shear uses rolled web yielding
for these two actual records. Other shear branches remain protected by accepted
synthetic tests, not claimed as an expanded real catalog. Other members, families,
noncompact/slender flexure, stiffened webs, holes/copes, cantilevers, axial/minor-axis/
torsion/interaction, force generation and bracing design remain outside scope.

Per-check section requirements (all positive finite, SI):
- Shear: depth, width, web/flange thickness, root radius.
- Flexure: those five plus plastic/elastic major-axis section modulus, minor-axis
  radius and inertia, J and Cw.
- Both need validated Fy/E, identity and physical geometry; flexure needs Zx>=Sx.
A corrupt resource is rejected globally. Fault-injected missing flexure-only data
cannot pass flexure and does not prevent an otherwise valid shear check. Overall
assessment remains INCOMPLETE. No numeric zero is substituted for missing data.

## Request contract

Public function `from strd.assessment import assess_member`; accepts object and
returns a fresh JSON-compatible dictionary. Full runnable request: `examples/a2_member.json`.
Every documented field is required; unknown keys are rejected to prevent silently
ignoring unsupported actions. No coercion from strings or bool to numbers.

Top-level fields:
- schema_version = STRD-MEMBER-1
- basis_id = DPT-STEEL-MANUAL-ISBN9789744585974-H-BENDING-SHEAR-v1
- catalog_revision, member_id, section_id, material_id: explicit identities
- length_mm: positive finite physical member length
- assumptions: six explicit true booleans: prismatic_undamaged,
  support_twist_restrained, segment_ends_braced, major_axis_only, web_plane_only,
  unstiffened_web. A false value is unsupported, not a default assumption.
- segments: nonempty ordered list of {segment_id, start_mm, end_mm,
  continuous_restraint}. Unique IDs, first start=0, exact contiguous endpoints,
  positive lengths and final end=length_mm. No gaps, overlaps or hidden tolerance.
- cases: nonempty list of {case_id, method, action_source, segments}; unique case IDs;
  method is ASD or LRFD, action_source is nonempty caller provenance text.
- Each case's segments: exactly one {segment_id, moment_knm, shear_kn, cb,
  cb_source, cb_reference} for every physical segment, no missing/duplicate/unknown IDs.

Moment and shear are finite nonnegative maximum absolute demands over that segment
on the selected method basis. Service does not create combinations, infer signs,
apply factors to demands, check equilibrium or combine unrelated maxima into an
interaction case. ASD and LRFD cases coexist but are never numerically mixed.

Lb=end-start; continuous_restraint=true explicitly sets Lb=0 for the strength check
while retaining actual physical coverage. Assertions do not design the restraints.
Cb is supplied: CONSERVATIVE requires 1; VERIFIED_MOMENT_DIAGRAM requires nonempty
reference and the inherited [1,5] bound. The service does not verify caller evidence;
use the accepted moment_gradient_factor helper where applicable to compute Cb.

## Results, freshness and coverage

- INVALID_INPUT: malformed/incomplete request or corrupt catalog; no overall capacity.
- UNSUPPORTED: unsupported top-level identity, method or member applicability.
- INCOMPLETE: at least one per-check INVALID_INPUT/UNSUPPORTED; valid other checks
  retained, any known failure remains visible via has_strength_failure.
- CHECKS_FAIL: complete requested coverage with one or more individual FAIL results.
- CHECKS_PASS: every requested flexure/shear check completed and passed.

records retain method, case ID, action source, physical segment, both checks, inputs,
intermediates, capacities, utilization, governing state, references and exclusions.
coverage records expected/completed count and complete flag. governing reports
maximum utilization separately for flexure/shear across the supplied checks, retains
all exact ties and marks partial when any check is incomplete. It is a summary of
individual checks, not an interaction formula. The top-level not_checked is always
present; PASS never implies whole-member, serviceability or stability acceptance.

Resolved records are frozen. Returned JSON dictionaries are independent copies so
caller edits do not mutate engine/catalog state. data_snapshot includes source hashes,
revision and exact SI inputs. snapshot_sha256 identifies canonical JSON of request,
data and assessment version. It is reproducibility/freshness evidence, not a digital
signature, durable project format or independently certified result. Request order is
preserved; identical requests/data/version produce identical output. P1 must invalidate
results on any edit; P2 must define save/open and version migration separately.

CLI after installation: `python -m strd.assessment FILE.json` or `-` for stdin.
UTF-8 files, finite JSON output. Exit 0 CHECKS_PASS, 1 CHECKS_FAIL, 2 invalid/unsupported/
incomplete or read/JSON errors. The CLI is an engineering entry point, not product UI.
