## Architecture and flow

Small modular Python package. No framework, plugins or empty future-layer scaffolding.

- src/strd/domain/contracts.py: typed dictionary requests/results and method/status types.
- domain/properties.py: immutable SI base records, read-only H property protocol.
  No example defaults in general property records. Construction is not verification.
- domain/validation.py: shared strict scalar rule (bool is not an engineering number).
- reference/ms1.py, ms2.py: original immutable fixed book fixtures, not a catalog.
- engineering/dpt/basis.py: source identity, historical contract IDs/versions and factors.
- classification.py, flexure.py, shear.py, moment_gradient.py: retained book equations.
- continuous_bending.py: MS1 validation/comparison/trace semantics.
- checks.py: MS2 validation, applicability, strength comparison and trace assembly.
- api.py: supported dictionary entry points binding fixed records to explicit-property kernels.
- src/strd_verified: thin compatibility facades/fixture exports and original smoke commands.

Dependency direction: public API -> fixtures + engineering; fixtures -> property types
and basis metadata; engineering -> domain and same-basis modules; domain -> stdlib.
Core never imports fixtures, compatibility, legacy or presentation. Calculation has no I/O.
Request -> strict shape/scalar/identity validation -> explicit assumptions/applicability ->
retained kernel -> ASD/LRFD comparison -> fresh trace + status + explicit not_checked.
Invalid/unsupported results do not acquire capacity/utilization or misleading PASS.

TypedDict preserves the existing dictionary/JSON representation without unnecessary
conversion hierarchy. Public entry points accept object for invalid-payload classification;
annotations do not replace runtime validation. py.typed is shipped; no static checker
pass is claimed. Private underscore kernels are testing/orchestration details, not
an authorized arbitrary-property catalog API. Public scope remains the single fixture.

## Compatibility and numerical policy

New canonical imports from strd; existing strd_verified public functions, required
fields, fixture values, statuses/messages, trace/units and smoke output retained.
Both import paths match 527 baseline captured responses. Independent Decimal/book
checks remain the numerical oracle; frozen responses only prove migration preservation.
Five retained kernel bodies are AST-identical. MS1 uses N-mm comparison; MS2 compares
reported public-unit capacity. These policies remain distinct. No Lr/Cv smoothing,
intermediate rounding, new Cb assumptions or zero-capacity substitutions.
Historical basis_id/calculator_version MS1-1/MS2-1 retained; distribution version
strd-engine 0.1.0 identifies packaging separately, not a changed equation revision.

Intentional changes: normal imports and smoke commands require installation under
src layout; use scripts/run_tests.py --source for explicit source-only development.
Root-only imports without installation are not retained. Legacy CLI paths are retired.
The old tools distribution is not silently uninstalled from user environments.
Private regression fixture bindings/aliases are retained only where accepted tests need
them. Undocumented private imports, __module__, class repr/pickling and arbitrary
monkeypatches are not promised compatible. No project/pickle format was supported.
External callers outside this repo cannot be inventoried here.
